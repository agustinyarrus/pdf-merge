# Verification

The rule: pdf-merge is checked against something **independent**. A parser that reads what its own writer wrote proves nothing; qpdf, pypdf and PDFium do.

## Go tests

```powershell
go test ./...
.\build.ps1 -Test     # go vet + go test and then builds
```

61 tests in `cli`, `fsx`, `textdist`, `tui`, `win/desk`, `pdf` (parser, page selection, merging, deduplication and Tarjan's components) and `pdfmerge` (the warnings wrapped at the window's width and the value of "Repetidos fusionados"). Seven in `pdf` read test PDFs: they look for the folder in `$env:PDF_FIXTURES` or, if it isn't set, `%TEMP%\pdf-merge-fx`, and if it doesn't exist they're skipped without failing. To generate it:

```powershell
.\scripts\fixtures.ps1                    # needs Python with pillow, pikepdf and reportlab
.\scripts\fixtures.ps1 -Dir D:\fx\pdf     # in another folder; then $env:PDF_FIXTURES = 'D:\fx\pdf'
```

There's also a dependency test: `go list -deps` on `tui` and the exe can't pull in `net`, `net/netip` or `os/exec`.

## Oracles

Requirements: Python 3 with `pip install -r internal/pdf/_oracle/requirements.txt` (numpy, pikepdf, Pillow, pypdf, pypdfium2 and reportlab, in the versions it was verified with).

```powershell
.\internal\pdf\_oracle\all.ps1 [-Corpus lista.txt] [-Fx carpeta] [-Work carpeta]
```

It builds pdf-merge, runs everything and ends with a summary card. `-Fx` is the fixtures from `scripts\fixtures.ps1` (by default, the same ones the tests read); `-Work` is where the exe and the outputs end up (by default `%TEMP%\pdf-merge-oracle`). The corpus is a text file with one PDF path per line, for example:

```powershell
Get-ChildItem $HOME\Documents -Recurse -Filter *.pdf | ForEach-Object FullName > corpus.txt
```

Without a corpus, only the stages with hand-built cases run.

| Stage | Script | What it checks |
|---|---|---|
| Go tests | `go test ./internal/pdf/` | parser, merge, deduplication, Tarjan |
| fixtures | `verify.py` | ranges, reverse, object streams, a page with an image |
| bookmarks and links | `outline_cases.ps1` + `outline_check.py` | 6 cases, including named destinations in all their forms |
| encryption | `crypt_check.py` | 13 cases: R2–R6, user and owner password, encrypted object streams |
| forms | `list_forms.py` + `form_check.py` | unique fields, no orphan widgets, each one with its original value |
| sweep | `sweep.py` | each PDF of the corpus merged on its own |
| stress | `bigmerge.py` | the whole corpus in a single PDF |

`verify.py` is the triple oracle the other stages use:

- **qpdf** (through pikepdf): strict structural check. Only new warnings count, not the ones the source already had.
- **pypdf**: the page count and the text of each page, in order.
- **PDFium** (Chrome's engine, through pypdfium2): each merged page rendered and compared pixel by pixel with the original.

With a corpus of 56 real PDFs (generated by Chrome in several versions, iTextSharp, SAP NetWeaver, reportlab and others), all 56 pass. Merged all together they give 352 pages in about 2 s, and deduplication brings 94.6 MB down to 21.8 MB.

`streamdiff.py` and `dictdiff.py` are diagnostic tools: they compare source and output streams and dictionaries to find where they differ.

### Lessons

The oracles found six defects the internal tests didn't see:

- Real numbers were rounded to 6 decimals. The `/FontMatrix` of the Type 3 fonts Chrome generates (1/2048) ended up as 0.000488 and the bold was drawn 0.06 % smaller. Now the shortest representation that round-trips to exactly the same float64 is used.
- Xref streams carry the PNG "Up" predictor, and it has to be reverted before reading them.
- When `/Length` is an indirect reference, it has to be resolved to cut the stream exactly.
- There can be garbage before `%PDF-` (the standard tolerates it in the first KB).
- In revisions 2 to 4, passwords go in PDFDocEncoding: an "ñ" is the byte 0xF1, not UTF-8's two bytes.
- Warnings the source PDF already had showed up as if they came from the merge. The oracle now compares them against the source's.

## In the CI

Every push runs [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) on `windows-latest`, with the minimum Go from the `go.mod` (1.26.0): Python 3.12 with the packages from [`requirements.txt`](../internal/pdf/_oracle/requirements.txt), `gofmt`, `go mod tidy -diff`, `go vet ./...` (also with `GOOS=linux`), the test PDFs with `scripts\fixtures.ps1`, all the tests with none skipped with the summary from [`.github/pruebas.ps1`](../.github/pruebas.ps1), `build.ps1` and the `.exe` with its version and its commit, `all.ps1` without a corpus (the hand-built stages: `pdf` tests, fixtures with the triple oracle, bookmarks and links, encryption) and, at the end, `SHA256SUMS` and the `.exe` as an artifact. The sweep of real PDFs doesn't run there: they're private documents and don't travel with the repo.

The CI hadn't run on GitHub yet (the repo hadn't been published). It was validated with [actionlint](https://github.com/rhysd/actionlint) and simulated on the development PC: a clean clone, Go 1.26.0, empty caches, a freshly created Python 3.12 and the workflow's `run:` steps with the same PowerShell wrapper the runner uses. All green.
