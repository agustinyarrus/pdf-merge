# The pdf-merge demo

`demo.gif` and `demo.webm` are a real recording, not a mockup: a 100×30 terminal runs
pdf-merge built from this repo on a folder with test PDFs. What you see is the real output
of that run.

| Moment | What you see |
|---|---|
| 0 to 4.9 s | `pdf-merge informe.pdf@1-4 escaneo.pdf@impares facturas -o legajo.pdf` is typed: the first four pages of the report, the odd ones of the scan and the folder of invoices, in that order |
| 4.9 s to the end | each file read (in the order they finish being read) and the card: 6 files, 16 pages, 43.8 MB that end up as 21.7 MB, 16 repeated objects merged, 8 bookmarks and the time |

**The bar goes by in one frame.** pdf-merge reads the PDFs in parallel with the same bar as img, and
then narrates the stages (merge, look for repeats, write) on a live line. With these 44 MB
everything takes about 50 ms: the reading bar shows up in a single frame of the GIF (at 4.92 s) and the
stages, in none. The scene wasn't inflated nor the program slowed down so it can be seen: that's how long it takes.

The output is correct, not just fast: this scene's `legajo.pdf`, run through the triple oracle
of [`verify.py`](../internal/pdf/_oracle/verify.py), gives a valid structure for qpdf, the 16 pages
with their text in order for pypdf and 0 pixels different from their originals for PDFium.

## What's here

| File | What it's for |
|---|---|
| `demo.tape` | the [VHS](https://github.com/charmbracelet/vhs) script: it sets up the scene off camera, records and tears it down |
| `preparar.ps1` | sets up the scene (or tears it down with `-Limpiar`): it builds pdf-merge and generates the PDFs |
| `generar.py` | the test PDFs, with reportlab |
| `demo.gif` · `demo.webm` | the recording: 8.9 s at 25 frames per second, 1078×644, 120 KB and 96 KB |
| `demo.png` | the last frame, with the card (for those who ask for less motion) |

## The PDFs

All test files, generated by `generar.py` with a fixed seed and reportlab in invariant mode (no
date or random identifier): the same bytes on every run.

| File | What it is |
|---|---|
| `informe.pdf` | 12 pages of text, with one bookmark per chapter (three pages each) |
| `escaneo.pdf` | 16 "scanned" pages: a JPEG image of ruled paper, A4 at 300 dpi, different on each page (43 MB) |
| `facturas\factura-01.pdf` … `04` | one page each, with the same logo: pdf-merge stores it only once (the 554 KB of "repeated objects merged") |

## Re-recording with VHS

You need Windows, PowerShell 7, Go and Python with the oracles' packages
(`pip install -r internal\pdf\_oracle\requirements.txt`: `generar.py` uses numpy, pillow and
reportlab), and also:

```powershell
winget install --scope user charmbracelet.vhs tsl0922.ttyd Gyan.FFmpeg
```

**Watch out for the VHS version.** 0.12.0 (winget's as of Sep 28, 2026) records the frames but
generates neither the GIF nor the WebM, without giving an error: it cancels the recording's context and passes it to
ffmpeg. It's fixed in 0.12.1:

```powershell
go install github.com/charmbracelet/vhs@v0.12.1     # needs Go 1.26.7+; Go downloads that version on its own
```

VHS draws the terminal in a windowless Chrome or Edge: it uses whichever is installed, it doesn't download
Chromium. Then, from this folder:

```powershell
Remove-Item Env:NO_COLOR -ErrorAction SilentlyContinue     # if your environment defines it, the demo comes out without color
vhs demo.tape                                             # demo.gif and demo.webm
ffmpeg -y -sseof -0.5 -i demo.gif -frames:v 1 -vf "split[a][b];[a]palettegen[p];[b][p]paletteuse=dither=none" demo.png
```

It takes half a minute. Always look at the result before publishing it: individual frames with
`ffmpeg -ss 6 -i demo.gif -frames:v 1 cuadro.png`.

### What the scene does, and why

- **Nothing from your machine on screen.** The PDFs are test files and the folder is `X:\docs\obra`, not your
  path: `preparar.ps1` generates everything in `demo\.escena\docs\obra` and mounts `demo\.escena` as a drive
  with `subst` (the first free one of X, Y, Z, W, V). pdf-merge shows the names the way they were
  passed to it, relative to the folder. `-Limpiar` unmounts the drive and deletes `.escena` (it's in
  `.gitignore`).
- **pdf-merge from this repo.** `preparar.ps1` builds it without a stamped commit: the header says
  `v1.0.0`, not `v1.0.0+abc1234`.
- **The prompt is `>` and nothing else**, without history suggestions (they'd be the recorder's), with
  the command line's colors in pdf-merge's palette. The tape sets them off camera.
- **The wait is the real one.** The tape doesn't sleep a fixed time after Enter: it waits for the
  card to say `Tiempo` and only then counts the 4 s of reading time.

### Style

The same as the family's other demos: background `#0b0b0f`, text `#cdd6f4` and the accents from
`internal/tui/color.go` as the theme's ANSI colors; Cascadia Mono 16; 1078×644 px, which with a 24 px
margin gives 100×30. Typing at 55 to 70 ms per key. 25 frames per second: at 50, the browser can't
capture every frame in time and the video comes out sped up.

## Without VHS

The same session can be recorded by hand, with a screen recorder like
[ScreenToGif](https://www.screentogif.com) on a 100×30 terminal with a `#0b0b0f` background and
Cascadia Mono (`wt --size 100,30 pwsh -NoProfile`). From this folder:

```powershell
$demo = $PWD.Path
$env:Path = "$demo\.escena\bin;$env:Path"
Set-Location (.\preparar.ps1)            # sets up the scene and goes in
pdf-merge informe.pdf@1-4 escaneo.pdf@impares facturas -o legajo.pdf
Set-Location $demo; .\preparar.ps1 -Limpiar
```

## Tearing it down by hand

If a recording got cut off and the `X:` drive was left behind:

```powershell
.\preparar.ps1 -Limpiar
```
